# USAP Roadmap

Public planning document. Everything below is either shipped, in flight, or queued. **No promises on dates** — this is an open-source project with a single primary maintainer right now; cadence depends on contributor velocity. Each line links to the issue or PR where the work lives once it starts.

## Shipped (highlights since v1.0.0)

See [`CHANGELOG.md`](CHANGELOG.md) for the full list. The headline items:

- 79 skills across 12 active domains (was 56 / 9 at v1.0.0).
- 12 `cs-*` orchestrator agents (was 5).
- Typed 11-field output contract enforced in CI on every committed sample.
- Framework mappings (`metadata.frameworks.*`) drive auto-generated MITRE ATT&CK Navigator + NIST CSF 2.0 coverage docs, with a drift gate in CI.
- Three stdlib validators (`tools/validate_skill.py`, `tools/validate_invocation_control.py`, `tools/output_contract.py`) and a deterministic sample generator (`tools/regen_samples.py`).
- USAP Design System imported into `docs/design-system/` — 10 React components, 5 token files, 3-screen UI kit, all from the Signal Architecture language.
- MkDocs Material docs site at <https://jaskaranhundal.github.io/usap-skills/>.
- `SECURITY.md` disclosure policy + live `SELF-AUDIT.md` (six checks, all green).

## In flight (this quarter)

- **Backfill `metadata.frameworks.*` across the remaining ~70 skills.** Only 10 carry MITRE ATT&CK arrays today; the goal is 60+. Tracked openly in `mappings/mitre-attack/coverage-summary.md` — that file is regenerated by CI, so progress is visible without me writing a blog post about it.
- **MCP server adapter.** A first-class MCP server wrapping the cs-* agents so they can be invoked from MCP-aware clients (Claude Code, Cursor, Goose, Codex CLI). Spec discussion is in [`standards/frontmatter-spec.md`](standards/frontmatter-spec.md) "Invocation Control"; the implementation will land as `tools/mcp_server.py` (stdio + http modes).
- **Replace the 59 generator-emitted sample payloads with real tool output.** Today the contract validator passes against generator-emitted baselines (deterministic, contract-conformant, but explicitly marked as such in the `rationale` field). The replacement is each `*_tool.py` actually producing a payload from a recorded fixture input. Issue: `#good-first-issue` per skill.
- **Scheduled-persistence operating model.** Hermes-style cron skills: run `attack-surface-management`, `secrets-exposure`, `iac-security` on a schedule and post deltas to a webhook. The shape is documented in `docs/research/usap-enhancement-roadmap.md` §3 (local-only); the issue is "should this live in usap-skills, or in a separate `usap-runner` repo?"

## Next (queued, not started)

- **`container-k8s-security/` domain** (3–4 skills): pod security, image vuln scan, runtime drift. Same scaffold pattern that `webapp-security/` followed.
- **`phishing-defense/` domain** (2–3 skills): URL classification, header analysis, take-down workflow.
- **First-class invocation-control extensions for Cursor and Goose.** Today the optional Claude Code extensions in the SKILL.md frontmatter (`disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `context`, `paths`, `model`, `effort`) cover one client. Cursor and Goose have analogous shapes; the spec doc will absorb them.
- **Per-skill Jinja prompt overlays.** Today every skill prompt is a static markdown file. Some skills (the SOC ones especially) benefit from per-environment overrides — e.g. "we're an AWS shop, drop the GCP examples." The shape is a separate `<skill>/overlays/<env>.md` that the runner merges. Will land alongside the MCP adapter.
- **Awesome-list submissions.** See [`LAUNCH.md`](LAUNCH.md) for the target list. Two per week, manually filed.

## Open invitations

These are explicit asks for community contribution. They have no owner today; pick one and open a PR.

- **Translation of `cs-security-analyst.md` (Alex)** into one non-English language. The skill is the single entry point for Lite mode; a German / Spanish / Japanese / Hindi version is high-leverage.
- **A second hand-authored `sample_output.json`** for any skill that doesn't already have one. The faithful samples (`appsec-devsecops/threat-model`, `vuln-scan`) are the canonical model; we want more.
- **A skill we haven't built yet.** Look at the 12 active domains; if you've shipped a workflow at work that should be a USAP skill, scaffold it from `templates/skill-template.md` and PR. The bar is "would a senior SOC / AppSec engineer agree this is a real-world workflow."

## Won't do (deliberate non-goals)

- A SaaS layer. The whole point is "no vendor cloud."
- Bundled vulnerability data. We map to frameworks; we don't ship CVE feeds.
- A GUI runtime. Use any LLM client; don't build your own.
- Per-language SDKs. The artifact is a system prompt + a Python tool; that's the SDK.

## How to influence this list

- File an issue using the `feature_request` template — it has the right shape.
- For new skills specifically, use the `new_skill` template.
- For substantial proposals (a new domain, a contract change), open a discussion first under "Ideas" before writing code.
